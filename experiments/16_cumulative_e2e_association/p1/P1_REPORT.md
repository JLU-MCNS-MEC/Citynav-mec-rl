## 2. 累计 E2E 与奖励

单步：

```
e2e_t = T_encode + T_comm(d_t) + T_infer(model_t)
C_episode = sum_t e2e_t
```

两种奖励：

| 方案 | 每步奖励 | 终止处理 |
|---|---|---|
| **A**（纯累计时延） | `-e2e_t / 100` | 无额外项 |
| **B**（失败感知） | `-e2e_t / 100` | 非成功终止时额外 `-50` |

- 归一化常数 `NORM_MS = 100`（基于 Train/Dev 的每步 E2E 分布，均值约 74 ms；不使用 Val-Seen）；
- 失败惩罚 `FAIL_PENALTY = -50`，约等于一个典型失败 Episode 的归一化累计成本（约 4000 ms / 100）；
- B 仅做奖励塑形，不引入 SR 约束、能耗约束或 CMDP；
- 折扣因子 γ=0.99，终止时 `done=1` 不 bootstrap。

**E2E 可重算验证**（示例：birmingham_block_9，71 步，OOB 失败）：

| 项目 | 值 |
|---|---:|
| 每步 e2e 之和（重算） | 3627.923615 ms |
| 环境报告累计 E2E | 3627.923615 ms |
| 误差 | < 1e-12 |
| 前 5 步 | 35.399 / 35.399 / 35.551 / 35.733 / 35.946 ms（encode 5.450 + comm 25.98–26.53 + infer 3.967） |

## 3. A/B 短程训练对比（DQN，200 episodes each）

| 指标 | A（纯累计） | B（失败惩罚） |
|---|---:|---:|
| Dev SR | **0.4167** | 0.3833 |
| Dev 平均累计 E2E | **2381.7 ms** | 2738.7 ms |
| Dev P95 累计 E2E | **4270.7 ms** | 7236.7 ms |
| Dev 平均步数 | **59.5** | 70.6 |
| premature_stop 比例 | **5.0%** | 11.7% |
| OOB | 31 | 27 |
| success | 25 | 23 |
| premature_stop | 3 | 7 |
| step_cap | 1 | 3 |

训练曲线（每 50 episodes）：

| 区间 | A reward | A cum E2E | A SR | B reward | B cum E2E | B SR |
|---|---:|---:|---:|---:|---:|---:|
| 1–50 | −40.5 | 4054 ms | 0.480 | −66.6 | 4056 ms | 0.480 |
| 51–100 | −40.3 | 4033 ms | 0.480 | −69.4 | 4136 ms | 0.440 |
| 101–150 | −40.6 | 4058 ms | 0.440 | −69.7 | 4072 ms | 0.420 |
| 151–200 | −38.1 | 3814 ms | 0.340 | −75.9 | 4091 ms | 0.300 |

**观察**：
1. 两种奖励都**没有出现大规模“提前 Stop 换低 E2E”捷径**：最短失败为 OOB（6 步）或 premature stop（8–9 步），E2E 424–650 ms，但占比仅 5–16%。
2. B 的失败惩罚**没有改善**行为：SR 更低、步数更多、premature_stop 比例更高（11.7% vs 5%）。
3. A 的累计 E2E 与 SR 均优于 B。
4. 200 episodes 内两者 SR 均有下降（0.48 → 0.34/0.30），说明短程 DQN 尚未收敛，正式训练需 4000 episodes。

---

## 4. 奖励方案决定

**采用方案 A（纯累计 E2E 时延）作为正式 DRL 的共同奖励。**

理由：
- A 在 Dev 上 SR 更高（41.7% vs 38.3%）、累计 E2E 更低（2382 vs 2739 ms）、premature_stop 更低；
- 未观察到通过错误 Stop 获得低累计 E2E 的失败捷径；
- B 的失败惩罚反而增加了失败率与步数。

**风险控制**：正式训练中持续监控 premature_stop 与 SR；若出现捷径（例如 SR 显著下降而累计 E2E 显著下降），如实报告，不解释为效率提升。
