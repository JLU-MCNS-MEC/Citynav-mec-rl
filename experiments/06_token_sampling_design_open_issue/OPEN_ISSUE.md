**状态：OPEN / BLOCKED**

- 创建：2026-10-29
- 影响范围：Token 生成、窗口采样、数据压缩、训练覆盖率、任何 Token v2 方案
- 约束：在用户明确同意方案前，**不得进行大规模 Token v2 生成**；不得用人为调整
  损失权重替代数据问题的分析。

## 已证实的事实

来自 `../visual_encoder_citynav/token_alignment_audit_20261029/REPORT.md`：

1. 当前每条轨迹固定取 2 个 8 步窗口（`total//3` 与 `total-8`），每条轨迹只监督
   16 步；625/22,002 条 Train-Seen（2.84%）、8/24 张地图进入训练。
2. 动作分布被采样改变：
   - Stop：全量 0.53% → 采样 6.25%（约 **12× 过采样**）
   - GoUp：全量 16.22% → 采样 3.72%（约 **0.23× 欠采样**）
   - GoDown：40.27% → 50.13%
   - MoveForward、TurnLeft、TurnRight 接近原始比例
3. 原因是两个固定窗口系统性漏掉轨迹早段：GoUp 平均相对位置 0.321（45.6% 在
   前 20%），GoDown 0.586，Stop 0.994。早段上升几乎不被采样，末段下降和终止
   被反复采样。
4. 动作召回失败不只是比例问题：在 token 审计的三个 arm 中，Stop 召回全部为 0，
   TurnLeft 全部为 0，TurnRight 只有一个 seed 非零；即使 h16 历史修正也没有
   改变这一点。
5. 轨迹点数与教师动作数的相关只有 0.19–0.27（实验 01），说明“按轨迹点数采样”
   不能代表动作覆盖。

## 尚未验证的假设

- 轨迹阶段覆盖（早/中/晚）是否比单看类别比例更能解释 Stop/Turn 的失败。
- 窗口之间的样本相关性（同一条轨迹的 2 个窗口）是否放大了少数轨迹的影响。
- 是否需要按动作阶段分层采样，或对整条 episode 做稀疏但覆盖全程的采样。
- 动作与状态的对应关系是否被窗口截断破坏（例如历史不足 16 步的边界样本）。

## 为什么 BLOCKED

当前优先级是先完成：

1. 实验 02：500 步上限下 full 模型的闭环复测；
2. 实验 03：MEC-V8.2 与 CityNav 数据流审计；
3. 实验 04/05：STOP/历史一致性与 Transformer-M 过拟合诊断。

在这些证据出来之前，重新设计 Token 采样会把多个变量混在一起，无法判断收益
来自数据覆盖、STOP 语义还是模型结构。因此本问题保持 OPEN，不启动 Token v2。
