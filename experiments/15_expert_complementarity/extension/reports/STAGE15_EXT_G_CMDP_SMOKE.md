# Stage 15-Extension · G 双约束 CMDP 功能验证（300 episodes）

日期：2026-11-25
运动学：**v = 3 m/s**（按用户指定）
预算形式：**相对预算** `B_task = 1.2 × E_minlatency(task)`，同任务、同运动学下测得
约束：能耗 `E/B ≤ 1`；成功率 `SR ≥ 0.50`
算法：PPO + Lagrangian 对偶上升（reward 只用 Stage-16 variant A，能耗与 SR 只进约束）

## 2. 训练结果（300 episodes，seed 42）

| 指标 | 约束版 | 无约束消融 |
|---|---:|---:|
| Dev SR（ep 300） | **0.333** | **0.333** |
| Dev E/B 均值 | 0.90 | 0.90 |
| Dev 超预算比例 | 0.12 | 0.12 |
| Dev 累计 E2E | 2818 ms | 2812 ms |

| 训练后 50 episode SR | 0.300 | 0.300 |
| NaN 奖励 | 0 | 0 |
| 最终策略 | **全部选 node 6（TM）** | **全部选 node 6（TM）** |

**机制验证通过的部分**：
- 能耗按真实导航动作逐步计费，预算比例、违约率逐 episode 正确统计；
- λ_SR 随失败率上升而上升（0 → 4.24），λ_E 在早期 E/B > 1 时升到 13.4、后期回落；
- 无 NaN、无 CUDA 错误，300 episodes 稳定跑完（770 s / 802 s）。

**没有验证成功的部分**：
- 两个 run 的策略与指标**完全一致**，都塌缩到"永远选 TM"的退化策略；
- 300 episodes 远不足以学到有效关联策略（Stage 16 需要 4000 episodes，
  且 300 步的 PPO 在 SR 0.33 上停住，低于 Min-Latency 的 0.45 和 TS 的 0.59）。

## 3. 关键结构性发现：能耗约束对"关联动作"几乎没有梯度

v = 3 m/s 下能耗分量（同一批 100 任务）：

| 分量 | 占比 | 由什么决定 |
|---|---:|---|
| 移动 | **94.79%** | 导航轨迹与速度（关联动作无法改变） |
| 等待（编码+通信+推理） | **2.39%** | 关联动作唯一能影响的项 |
| 辅助 | 2.82% | 平台固定功耗 |

不同 MEC 节点之间的差异只有推理时延（0.5–20 ms）与通信时延（24–126 ms），
折算到能耗上是总能耗的 **2.4%**——而每步移动能耗约 168–284 J。
也就是说：**关联决策最多能改变 2.4% 的能耗，而 95% 的能耗由导航策略决定。**

因此：
1. λ_E 增大不会改变策略的关联选择（只是给一个几乎常数项加权）；
2. 两个 run 因此表现得一模一样；
3. 把"能耗预算"挂在 MEC 关联动作上，在当前能耗模型下**在结构上不可能起作用**。

## 4. 结论与建议

1. **工程上**：`env_constrained.py` + Lagrangian PPO 的管线可用，可复用于其他约束。
2. **科学上**：能耗约束在这个动作空间里是"空约束"。要让它有意义，必须改三件事之一：
   - **A. 让能耗依赖关联动作**：把机载编码功耗、上行发射功耗、MEC 侧计算功耗纳入模型，
     并让不同节点（或本地/卸载）在这些项上有量级差异（例如本地编码 15 W vs 卸载 30 W）；
   - **B. 把能耗约束挂到导航策略**（前进/转向/停止），导航才真正控制 95% 的能耗；
   - **C. 把能耗约束改成"每米能耗" J/m 并允许 agent 影响路径长度**——同样需要导航自由度。
3. **算法上**：300 episodes 只够做管线验证，任何 SR/约束满足的结论都需要 ≥ 1000–2000
   episodes，且应加基线对照（Min-Latency / TS）。
