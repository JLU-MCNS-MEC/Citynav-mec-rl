# Stage 15-Extension · G2 方案 A 能耗模型下的双约束 CMDP（300 episodes）

日期：2026-11-25
用户口径：**只计 UAV 编码能耗 + 通信能耗 + 等待 MEC 推理结果时的悬停能耗**；
不含飞行推进能耗，不含 MEC 侧计算能耗。

---

## 1. 新能耗模型

```
E_step = P_enc · t_enc  +  P_tx · t_comm  +  P_hover · t_infer
P_enc = 15 W（假设）, P_tx = 0.1 W（Stage 12 协议）, P_hover = P0 + Pi = 168.49 W
```

| 模型 | 推理时延 | 编码能耗 | 通信能耗 | 悬停能耗 | **E_step** |
|---|---:|---:|---:|---:|---:|
| Small | 0.495 ms | 0.0818 J | 0.0075 J | 0.083 J | **0.173 J** |
| Medium | 1.498 ms | 0.0818 J | 0.0075 J | 0.252 J | **0.342 J** |
| Transformer-S | 3.967 ms | 0.0818 J | 0.0075 J | 0.668 J | **0.758 J** |
| Transformer-M | 10.003 ms | 0.0818 J | 0.0075 J | 1.685 J | **1.775 J** |
| Large | 19.972 ms | 0.0818 J | 0.0075 J | 3.365 J | **3.454 J** |

**关联动作对能耗的影响从 2.4%（推进模型）提升到 20 倍（本模型）**，
这正是方案 A 要解决的问题。

100 任务（Min-Latency，v = 3 m/s）：

| 指标 | 值 |
|---|---:|
| 平均 / P50 / P95 | **46.9 J / 29.3 J / 128.7 J** |
| 分量 | 悬停 **89.5%**、编码 10.1%、通信 0.3% |
| 成功任务数 | 44 / 100 |

参考预算（Min-Latency，250 Train + 60 Dev）：均值 38.7 J、P50 27.5 J、P95 109.0 J；
预算 = 1.2 × 参考 ≈ 46.5 J。

## 2. 300 episodes 结果

| 指标 | 约束版（λ 学习） | 无约束消融（λ=0） |
|---|---:|---:|
| Dev SR（ep 300） | 0.350 | 0.333 |
| Dev E/B | 0.69 | 0.69 |
| Dev 超预算比例 | 20% | 20% |
| Dev 平均能耗 | 17.3 J | 17.2 J |
| λ_E（最大 / 最终） | 3.78 / **0.00** | 0 / 0 |
| λ_SR（最大 / 最终） | 4.54 / 4.54 | 0 / 0 |
| 最终策略 | **全部选 Medium 节点** | **全部选 Medium 节点** |
| NaN | 0 | 0 |

**机制验证（通过）**：
- 能耗现在随节点变化 20 倍，预算比例、违约率统计正确；
- λ_E 在早期 E/B > 1 时升到 3.78，策略学会选低功耗节点后回落到 0；
- λ_SR 因 SR 未达 0.5 持续上升到 4.54；
- 300 episodes 全程无 NaN、无 OOM。

**没验证到的**：
- 两个 run 最终策略完全相同（都塌缩到永远选 Medium，SR 0.333）；
- λ_SR 升到 4.54 也没有把 SR 拉上来——300 episodes 远不足以让 PPO 学到关联策略
  （Stage 16 的 PPO 需要 4000 episodes 才到 SR 0.62）。

## 3. 结论

1. 方案 A 的能耗模型按你的口径实现完毕，**关联动作现在真正影响能耗**（单步 0.17–3.45 J）。
2. 双约束管线（正确计费 → 预算比例 → 违约率 → λ 对偶上升 → PPO）全部打通。
3. 300 episodes 只能证明"管线能跑、约束会被触发"，**不能**回答
   "约束是否改善 SR/能耗权衡"。要回答这个问题需要：
   - 1000–2000 episodes（约 45–90 分钟/组）；
   - 与 Min-Latency（SR 0.448，能耗 38.7 J）和 Max-Quality（TS）对照；
   - 至少两档 slack（例如 1.2 与 0.8），才能看出能耗约束是"松"还是"紧"。
4. 当前策略能耗 17.2 J 远低于预算 46.5 J（E/B = 0.69），说明 **slack = 1.2 偏松**，
   真正有张力的设置应在 0.6–0.8 之间。
