# 多模态输入与防泄漏审计

> 结论先行：**没有发现把真实目标坐标、目标距离、教师未来动作直接喂给模型的证据。**
> 但存在一个必须写清楚的**任务级信息便利**：12 维目标信念在视觉匹配成功时，
> 等价于一个误差约 8–9 m 的"目标方向 + 距离"估计（近似 GPS-to-goal）。
> 这不算标签泄漏，但它显著降低了任务难度，也改变了 Stage 06 结果的解释方式。

## 1. 逐项输入

| 输入 | 维度 | 源数据 | 生成阶段 | 依赖真实目标坐标？ | 闭环可获得？ | 未来/教师泄漏？ | 训练/推理一致？ |
|---|---|---|---|---|---|---|---|
| 当前视觉 | 49×2048 | `heading_crop(x,y,yaw)` 100 m×100 m → 224² | 每次前向 | 否（只用当前位姿） | 是 | 否 | 是（单一路径，见 §3） |
| 目标参考 | 2048 | `north_crop(target)` 96 m×96 m → ResNet → L2 | 04 / 每步 | **是**（裁剪中心=真实目标） | 是（目标图像是任务输入） | 否（不是坐标数值） | 是（FP16 往返） |
| 历史视觉 | 16×2048 | 已执行状态的 pooled 特征 | 04 缓存 / 闭环实时 | 否 | 是 | 否（严格因果） | 是（FP16 精度一致） |
| 历史位姿 | 16×3 | 已执行状态，机头系相对量 | 同步构建 | 否 | 是 | 否 | 是 |
| 历史动作 | 16×4 | 已执行动作 one-hot | 同步构建 | 否 | 是 | 否 | 是 |
| 历史掩码 | 16 | 有效历史长度 | 同步构建 | 否 | 是 | 否 | 是 |
| 全局目标信念 | 12 | 24 m 候选库 × 目标嵌入的 top-5 匹配 + 相对几何 | 04 / 每步重算 | **间接近似**（见 §2） | 是 | 否 | 是 |

## 2. 目标信念到底携带了多少"目标位置"信息（实测）

方法：在 Val-Seen 的训练缓存上抽样（400 条 episode × 最多 5 个状态），把 belief 的第 3/4 维
（top-1 候选在机头系的前向/左向偏移）与第 5 维（top-1 距离）和**真实**的目标相对向量比较：

| 量 | 相关系数 | 误差 |
|---|---|---|
| belief[3] vs 真实前向偏移 dx_f | **0.994** | MAE 8.7 m |
| belief[4] vs 真实左向偏移 dy_l | **0.987** | MAE 8.6 m |
| belief[5] vs 真实距离 | **0.996** | MAE 7.5 m |
| 方向角误差（中位） | — | **4.4°** |
| 距离比 belief[5]/真实距离（中位 / p10–p90） | — | **0.992 / [0.80, 1.26]** |
| episode 内距离的 Spearman（中位） | **1.000**（98.3% 的 episode > 0.5） | — |

也就是说：在候选匹配正常的情况下，**12 维信念几乎就是目标在机头坐标系下的真实偏移**，
误差只有 8–9 m、方向 4° 量级。它不是"目标坐标输入"（没有把 `(tx,ty)` 直接送进网络），
但它是一个**视觉匹配得到的、精度接近标签的定位估计**。

### 2.1 为什么会出现这种便利

1. 目标参考图像是**以真实目标坐标为中心**、从**同一张地图**、**同一比例尺**裁剪的俯视图；
2. 候选库也是从**同一张地图**按 24 m 网格切出来的；候选嵌入与目标嵌入来自同一个冻结 ResNet、
   同样的归一化；
3. 因此"目标图像 ↔ 候选"的匹配本质上是在同一坐标系里做模板检索，top-1 候选自然非常接近真实目标。

这是一个**合理但必须声明的任务简化**：它把"视觉目标导航"变成了"给定同一地图的模板检索 +
局部视觉控制"。与官方 CityNav 的语言指令导航不是同一个难度（见
`LITERATURE_PROTOCOL_COMPARISON.md`）。

### 2.2 低有效目标时信念退化

目标 patch 有效比例 < 0.5 的 218 条任务 **SR = 0/218**，其中 37 条进入 20 m 仍未停；
有效比例 ≥ 0.75 的子集 SR = 26.2%。这与"信念是主要定位信号"一致：目标图像质量下降 →
匹配退化 → 导航与 STOP 同时失效。这是相关性证据，不是因果实验。

## 3. 训练与推理的一致性（已实测）

| 检查 | 结果 |
|---|---|
| 归一化 | 只有一条路径（uint8 → GPU → f32/255 → ImageNet mean-std）；缓存 vs 训练特征 `max_abs_diff = 0.0` |
| 弃用的 CPU 归一化路径 | 与 GPU 路径差 7.15e-7（3 ULP），经 fp16 放大到 0.125，故删除 |
| 编码 batch 差异 | batch 32 vs 128 特征差约 0.09（相对 0.2%）；闭环 batch=1，首步决策概率差 ≤2e-4（4 条抽样） |
| 历史因果性 | `history_block` 只读 `t-1..t-16`；契约测试通过；闭环只用实际执行状态 |
| 目标嵌入精度 | 训练缓存 FP16 → 模型侧 FP32；闭环同样 FP16 往返 |
| 信念重算 | 闭环每步用当前位姿重算，不使用缓存中教师状态的 belief |

## 4. 可能的泄漏通道逐项排查

| 通道 | 是否存在 | 证据 |
|---|---|---|
| 真实目标 xy 作为输入 | **否** | `model_v2.py` 只消费 7 个键；`to_model_batch` 不含坐标 |
| 真实目标距离作为输入 | **否** | 同上；距离只用于离线诊断与评测 |
| 教师未来状态/动作 | **否** | 历史来自执行缓冲；`test_history_is_strictly_causal`；03B 标签与闭环无关 |
| 教师中间路径 | **否** | 03B 只用起点/航向/目标；契约测试见 DATA_LINEAGE.md §3.3 |
| 评估信息回灌训练 | **否** | Val/Test 不参与训练；Test-Unseen 未读取 |
| 目标图像与候选库同源 | **是（任务设计）** | 见 §2.1；这是任务简化，不是数据泄漏 |
| 标签与输入同分布 | **是（模仿学习固有）** | 训练状态全部来自教师轨迹；这是分布偏移问题的根源（见 CLOSED_LOOP_FAILURE_AUDIT.md） |

## 5. 推理期输入扰动（仅提示，不是消融）

在 1,200 个教师强制 Val-Seen 状态上把单个输入置零（模型与权重不变，脚本
`scripts/probe_modalities.py`，结果 `results/modality_probe.json`）：

| 条件 | 准确率 | Macro-F1 | STOP 召回 |
|---|---|---|---|
| 正常 | 0.9419 | 0.7862 | 0.658 |
| belief 置零 | **0.1322** | 0.1775 | 1.000（退化为全 STOP） |
| 历史（视觉+掩码）置零 | 0.6953 | 0.5067 | 0.711 |
| 目标嵌入置零 | 0.9428 | 0.7881 | 0.658 |
| 当前视觉置零 | 0.9444 | 0.7776 | 0.500 |

**解释与警告**：置零输入远在训练分布之外，准确率下降不能直接当作因果重要性；尤其是
"目标嵌入置零几乎无影响"很可能是模型通过信念已经拿到了目标信息，而不是目标图像真的没用。
这组数字只用来支持一个结论：**模型对 12 维信念的依赖极强**，与 §2 的测量一致。
真正的模态归因需要重新训练（见 AUDIT_REPORT.md 的消融矩阵），本阶段不做。

## 6. 结论分级

- **已确认**：没有坐标/距离/未来动作的数值泄漏；训练与闭环的特征路径一致。
- **已确认（任务简化）**：目标图像与候选库同图同尺度，使 12 维信念成为近似 GPS 的目标向量
  （方向误差中位 4.4°、距离误差 ~8 m）。
- **有证据的推断**：模型主要依赖信念；低有效目标任务全失败与此一致；但这是相关性，不是因果。
- **未验证**：若把目标图像换成跨视角/跨地图，任务难度会上升多少——需要新实验。
